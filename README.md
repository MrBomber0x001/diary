# مذكرتي

A standalone memo and media library for books, games, films, personal notes, life planning, and shared reading. The SQLite database and uploaded files are stored on the machine running the server. Optional title lookup contacts Open Library for books, IMDb for films, and Wikipedia for games.

## React frontend

The client is a React 19 single-page application built by Vite. `src/App.jsx` owns authentication and route selection; reusable components and page modules under `src/components` and `src/pages` render the interface and call the existing same-origin `/api` endpoints. Client navigation uses the History API, item detail URLs (`/item/:id`) remain supported, and React renders user content as text rather than injecting saved HTML. The Express/SQLite API and its per-account authorization remain the source of truth.

The React UI currently covers sign-in/registration, today's summary, a cover-led and filterable library, book chapters and progress, a month-grid calendar, task list and Kanban board, task and routine controls, planning areas/goals/projects, reading lists and notes, Learning Hub topics/notes/files, a finance dashboard with cash-flow trends and an AI finance coach, book-club reading progress and conversation, interview applications and rounds, searchable and paginated question banks with CSV/JSON import, an adaptive AI interviewer, gallery uploads, focus sessions and XP, Quran/prayer times and Quran radio, and preferences/backups. Item reviews, notes, and chapter notes support Markdown headings, lists, quotes, links, and images with a preview while editing; image files can be dragged into text fields, and long saved text can be expanded on demand. Individual library items can open in a new tab. The top-bar notification center combines task deadlines, calendar events, subscription renewals, club messages, and habit/routine reminders; optional browser notifications are controlled in settings. Arabic/English switching sets RTL/LTR page direction and Markdown content detects direction independently, although some feature-specific labels remain Arabic. Global search, audio/ambience controls, club attachment upload/permissions, advanced quiz options, pins/backlinks, image editing, and some advanced filters/analytics still need dedicated React views. The old imperative app client and its HTML shell have been retired; all current browser UI is rendered from React components under `src/`.

The app supports multiple accounts. Each account has a separate library and signs in with a username and password of at least 12 characters. The first account created after this update takes ownership of any existing library entries. Sessions expire after 30 days. The database and uploaded files are not encrypted at rest, so protect the server's data folder and backups.

See the [authentication guide](./docs/authentication.md) for the registration and sign-in flows, session behavior, API endpoints, validation rules, and screenshots.

The first account is the app owner. The owner can manage automatic daily backups from **الإعدادات**, create a manual full backup, and download backups. Full `.zip` archives include the database, uploaded images, audio, book-club files, and Learning Hub attachments for all accounts; they are stored in `data/backups`, with the latest 7 backup files retained. The daily job runs while the app is running and checks hourly; when the owner signs in, it creates today's full archive if one is missing. Older `.sqlite` backups remain downloadable and can still be restored, but do not contain media.

The owner can optionally enable AWS S3 mirroring in **الإعدادات**. New image and audio uploads, plus generated backups, are copied to the configured private bucket while remaining stored locally. Configure AWS credentials on the server using the AWS SDK default credential chain (environment variables, shared credentials/config, or an IAM role); credentials are never stored in the app database or browser. The app tests bucket access before enabling mirroring. The AWS identity needs `s3:ListBucket`, `s3:PutObject`, and `s3:DeleteObject` for the selected bucket and prefix. Files are stored under the configured prefix in `media/<account-id>/images`, `media/<account-id>/audio`, and `backups`. Enabling mirroring applies to new uploads and backups; it does not migrate existing files.

To restore a full backup, open **الإعدادات**, select its ZIP file, and confirm **استعادة النسخة المحددة**. The app validates the archive and its SQLite database, creates a safety archive of the current database and media, then replaces the database and media together. You will be signed out and must sign in with an account from the restored database. Restoring an older `.sqlite` file replaces only the database; keep a separate copy of matching media if you need those files.

Choose Arabic or English in **الإعدادات**; language is saved separately for each account and switches the interface direction between RTL and LTR. The **طريقة تعديل العناصر** preference switches between inline editing and the edit popup. Choose light, dark, or system-matched appearance, adjust font size, typeface, and line spacing, and configure shortcuts for a quick task, today's note, the read-later list, and the create menu. Shortcuts use Ctrl+Alt+Shift plus a selected letter and are ignored while typing or while a dialog is open; Ctrl+K and Ctrl+N remain available. You can optionally enable browser notifications for task deadlines, timed events, subscription renewals, and the daily habits/routines nudge. New in-app notifications can play a short tone; control it separately from browser notification permission. Notifications are checked while the application is open, and the panel supports marking individual notifications or all current notifications as read. Completing every task due today opens a once-per-day congratulatory dialog.

Open **القرآن والصلاة** from the top bar to see prayer times, choose a Quran radio station, or select a surah for reading and audio playback. Start audio from the Quran workspace and use the persistent player to keep listening while navigating elsewhere in the app. Prayer coordinates and calculation method are read from **الإعدادات**; prayer times come from AlAdhan, surah text/audio from AlQuran Cloud, and radio streams from mp3quran.net. These services are contacted by the browser and their audio is not stored by the app. The **الماليات** workspace lets each account record income and expenses, review six months of cash-flow trends, search and filter transactions, track subscription renewals, and compare category budgets with actual spending. Its AI finance coach reuses the provider connection in **الإعدادات**; each analysis requires confirmation and lets you choose spending, budgets, subscriptions, and cash-flow data to share. Transaction descriptions and notes are excluded, and reports are saved to your account for later review or deletion. AI output is educational guidance, not professional financial advice. Choose a month with the month/year controls, sort and filter subscriptions, and page through long transaction or subscription lists. Subscription renewals are recorded only when you explicitly choose **تسجيل الدفع**; the app does not connect to banks or charge subscriptions. Set the default currency in **الإعدادات** (EGP by default). See the [finance AI guide](./docs/finance-ai.md) for details about shared data and report retention. Code snippets use a dedicated monospaced preview with a one-click copy action. The **جلسات التركيز** workspace includes duration presets, a visual timer, pause/resume controls, locally generated ocean-wave, rain, and breeze ambience with volume control, XP summaries, and a session history.

The **اليوم** workspace summarizes the day with actionable task and event lists, progress metrics, XP, and a trophy shelf. Today’s task checkboxes complete tasks without leaving the page. In the habit tracker, click any past or current day to add or undo its check-in; future days are disabled. Focus XP is awarded only after a focus session completes, at 1 XP per focus minute. Active subscriptions appear in the notification panel three days before renewal, on the renewal date, and while overdue. One gentle daily in-app reminder groups unfinished habits and routines; optional browser alerts are shown only while the app is open and browser notifications are enabled. Interview applications include status metrics, status/search filters, and pagination; mock-interview flashcards remain searchable and paginated within each topic.

The **المقابلات** workspace keeps job applications and interview records private to each account. Track company, role, status, application date, job link, and notes; add multiple interview rounds with questions and answers, questions for the interviewer, your experience and lessons, and follow-up steps. Set an optional interview start and end time to add the round to your calendar; rescheduling or removing the round updates its linked event. The **المقابلة التجريبية** view provides searchable, filterable question banks with tags, difficulty, sample answers, and answer notes; import question sets from CSV or JSON, preview them before saving, and automatically skip duplicates. Practice random, unpracticed, or previously weak questions in focused one-at-a-time sessions; write or record a response before revealing the sample answer, use an optional adjustable timer, and rate each answer as strong, needs work, or skipped. The **المحاور الذكي** runs adaptive interviews, analyzes each answer, asks relevant follow-ups, and saves an actionable end-of-session report and transcript. Each user connects an OpenAI-compatible provider from **الإعدادات**; provider keys are encrypted in the database with `PERSONAL_MEMO_AI_ENCRYPTION_KEY` and never sent back to the browser. Configure this environment variable as a random 32-byte secret encoded as 64 hexadecimal characters before connecting a provider; keep it stable and private, including when restoring backups. Provider endpoints must use HTTPS and resolve to public addresses. For each interview, users explicitly confirm sending answers and separately select whether the job description and resume should be shared. Transcripts and feedback are saved in the user's account; the AI report is a practice aid, not a prediction of hiring outcomes. Applications, interview rounds, topics, cards, practice sessions, AI connections, AI session history and responses, and saved finance AI reports are included in database backups.

See the [AI interviewer setup and data-handling guide](./docs/ai-interviewer.md) for key generation, provider endpoint restrictions, retention, and recovery requirements.

The workspace is organized into separate views for **اليوم**, tasks, calendar, planning, habits, your library, saved reading, interviews, daily notes, pinned items, and a personal image gallery, with a compact navigation rail on desktop and a multi-row section bar on smaller screens. **اليوم** opens first and brings together today's events, due tasks, habits, and routines. Its quick summary highlights completed, nearly-complete, and in-progress media plus overdue tasks; expand **عرض كل المؤشرات** for the full metrics. Tasks can be added inline, given a due date with one tap, filtered by today/upcoming/completed, and searched; switch between the list and a two-column Kanban board, where tasks can be dragged between open and completed (or toggled with the accessible checkbox). Use **تفاصيل** to add a time, project, or notes. Tasks can recur daily, weekly, or monthly; completing a recurring task creates its next occurrence. Overdue tasks stay highlighted and trigger an in-app alert while the application is open.

**التقويم** manages dated and recurring events in a month grid; select a day to see its events or add one directly to that date. Under **التخطيط** you can create life areas, connect goals to areas and projects to goals, and link tasks to active projects so each project has a visible next action. **العادات والروتين** shows today's completion progress, a seven-day tracker and streak for each habit, plus one-tap completion. Routines have their own daily completion action and step list. Its private trophy board ranks this week's habit, routine, and task activity: one point per completed task, two per habit log, and three per completed routine. **مراجعة الأسبوع** summarizes recent completions, overdue and upcoming tasks, and planning prompts.

The **قائمة المهام** section stores private, account-specific tasks with notes, due dates, reminders, recurrence, and completion state. The notification bell surfaces overdue tasks, tasks due today or soon, upcoming calendar events, subscription renewals, and a grouped daily habit/routine nudge; optional browser alerts can notify about tasks, events, subscriptions, and the daily nudge while the app is open. The **قائمة القراءة** section stores URLs with descriptions, selected excerpts, reading status, and Markdown reviews; filter by unread, currently reading, or completed, and update a status directly from its card. **الروابط المهمة** presents reference links as image-forward searchable cards with their domain, note, quick open, copy, edit, and delete actions; you can paste a URL from the clipboard to start a new bookmark. Use **جلب صورة وعنوان الصفحة** to retrieve a public page's title, description, and preview image; the image is validated and saved to the account's private uploads. The preview fetcher rejects private-network targets and limits redirects and download sizes. **مقاطع برمجية** stores private reusable code samples with a language and description, with search, copy, edit, and delete actions. **مركز التعلّم** organizes learning topics into Markdown notes with optional PDF, document, image, and text attachments; topics and files are private to each account, and attachments are included in full backups. The header search searches the library, tasks, articles, and bookmarks; library filters can narrow results by type, status, rating, and tag. Deleted library items, tasks, articles, and bookmarks can be restored using the temporary **تراجع** action.

The **الخط الزمني** view gathers dated writing, reading, completed media, tasks, habits, routines, calendar events, and article reading activity for a selected date range. **نادي الكتاب** lets members create private clubs, add books from their own library, track each member's page progress, and share messages or reading insights. Owners can create and revoke invitation links; links expire after 30 days and require an account sign-in. New members cannot add books until the owner grants that permission individually; owners can revoke it at any time. Members can mention other club members with `@username` to create an in-app notification, attach images and common documents, and share links in discussions. Members can schedule meetings with a date, link, and discussion notes, and edit their own meetings; owners can manage every meeting. The leaderboard gives 10 points for each completed shared book and 3 for each insight. The club metrics and export are available in the club view; the ZIP export contains `club.json` and shared attachments, while each member's private reading notes are only included for that member. Club uploads are stored in `data/club-uploads`; full backups include them. Membership, discussions, attachments, reading progress, and invitations are scoped to club members.

**مذكرة اليوم** provides one optional, Markdown-enabled page per date and saves edits automatically. Use `[[item:ID|عنوان]]` or `[[daily:YYYY-MM-DD|عنوان]]` to link a note or a dated entry; the linked page lists backlinks from your memos, daily notes, articles, and saved-link notes. The pin control saves library entries, articles, bookmarks, and daily notes to **المثبتة**. Use **وضع هادئ** to hide navigation, dashboard metrics, and other header actions while reading or writing; the account menu and an exit control remain available. **معرض الصور** stores private JPG, PNG, WebP, and GIF uploads in your account's image storage, groups them by a custom category (for example, art or personal), and provides a full-screen viewer with previous/next navigation. Removing an image from the gallery does not remove it from a note or other content where it is used.

Keyboard shortcuts: **Ctrl/Cmd+K** focuses global search, and **Ctrl/Cmd+N** opens the new-item form.

### Chrome extension

The unpacked Chrome extension is in `extension`. To install it, open `chrome://extensions`, enable **Developer mode**, choose **Load unpacked**, and select this folder's `extension` directory. Open the extension's settings and set the application URL (by default `http://127.0.0.1:4178`). Keep the app running and signed in in Chrome. On an article or website, click the extension and choose **حفظ في المقالات**; it sends the page title, URL, description, and selected text to the app in a new tab. Optionally include a bounded text snapshot of the readable page. The article is saved after the app session is authenticated, and the app confirms the save. The extension does not store or transmit your password or send page content to third-party services.

When adding a book, game, or film, enter a title and choose **البحث عن معلومات وصورة** to find matching details and cover art. The **بحث عن عنوان** side panel is also available from the library. You can upload your own JPG, PNG, WebP, or GIF cover image (up to 5 MB).

Reviews, notes, and chapter notes support Markdown headings, ordered and unordered lists, quotes, bold, italic, HTTP(S) links, inline code, fenced code blocks, and uploaded images. Images can be pasted directly from the clipboard or dragged into a Markdown editor. In **الإعدادات**, control Markdown rendering, the formatting toolbar, and image paste/drop per account. Long reviews and notes are shortened in library cards until expanded. On an item's detail page, edit its review or notes in place and preview the Markdown before saving. Each item opens in its own tab from its title or the **فتح في تبويب جديد** action. Books have a chapter list with a separate Markdown notes area for each chapter. Cover images can be selected, dragged onto the cover area, or pasted from the clipboard. Task, planning, and item actions use compact icon buttons with accessible names and hover labels.

Text fields and rendered notes detect the text direction automatically, so Arabic, English, and mixed-language text align naturally. The interface uses IBM Plex Sans Arabic; loading the web font requires an internet connection. Each item detail page can also store and play up to 10 audio attachments per upload request (MP3, M4A, WAV, OGG, WebM, FLAC, or AAC; up to 100 MB per file).

## Project structure

- `server.js` owns application startup, SQLite schema setup and migrations, authentication/session and storage/backup services, shared middleware, and the final error/static handlers.
- `routes/index.js` registers feature routers and supplies their dependencies from the application layer.
- `routes/auth.js` handles registration, login/logout, session status, and the authenticated account endpoint. It is mounted before the authenticated API middleware.
- `routes/planning.js` handles life areas, goals, and projects.
- `routes/activity.js` handles calendar events, habits, routines, the daily overview, timeline, weekly review, and metrics.
- `routes/tasks.js` handles task CRUD and recurring-task creation.
- `routes/interviews.js` handles job applications, interview rounds, and mock-interview question banks.
- `routes/ai-interviews.js` handles encrypted per-account AI provider connections, adaptive interviews, feedback, and reports.
- `routes/notes.js` handles saved articles, bookmarks, daily notes, backlinks, pins, and the personal image gallery.
- `routes/learning.js` handles account-private learning topics, Markdown notes, and note attachments.
- `routes/finance.js` handles account-scoped transactions, subscriptions, renewal payments, and monthly budgets.
- `routes/finance-ai.js` handles consent-gated finance analysis, aggregate-only provider requests, and account-private saved reports.
- `routes/book-clubs.js` handles clubs, invitations, member permissions, messages and attachments, meetings, progress, metrics, notifications, and exports.
- `routes/management.js` handles search, restore-from-trash, settings, and backup endpoints.
- `routes/discovery.js` handles external title lookup and bookmark previews.
- `routes/media.js` handles image/audio upload and authenticated media delivery.
- `routes/library.js` handles library items, reading progress, and book chapters; `routes/item-page.js` serves authenticated item pages.
- `src/` contains the React SPA entry point, reusable components, localized messages, route handling, and feature pages.
- Vite builds the React shell into `dist/`; Express serves that SPA while keeping the existing account-scoped API and SQLite backend.
- The browser app no longer injects the old HTML shell or loads the imperative browser script; Vite bundles the React styles and code as production assets. `test/` contains the isolated Node.js regression suite.

Keep database connections, authentication, and shared services in the application layer; put feature-specific HTTP handlers in their route module and pass shared dependencies into that module rather than importing the server entry point.

## Run

1. Install Node.js 22.12 or newer.
2. Open a terminal in this folder and run `npm install`.
3. Run `npm start` to build the React client and start Express.
4. Open `http://127.0.0.1:4178` in your browser.

For client development, start the backend with `npm start` and run `npm run dev` in a second terminal; Vite proxies API and media requests to Express and serves deep links through its SPA fallback. Run the isolated regression suite with `npm test`. Both startup and tests build the React client first. Tests use a temporary database and media folders and do not modify the normal `data` directory.

The SQLite database is created at `data/memo.sqlite`, uploaded images at `data/uploads`, and audio at `data/audio`. Back up these to preserve your library and attachments. By default, the server listens only on this computer. Set `PORT` to use another local port. Metadata lookup requires an internet connection; library content and uploaded images/audio are not sent to metadata providers.

For a remotely reachable self-hosted instance, configure `HOST=0.0.0.0` and put the app behind an HTTPS reverse proxy with a domain, firewall rules, persistent database/media storage, and reliable backups. Set `COOKIE_SECURE=1` when TLS terminates at the proxy so authentication cookies are sent only over HTTPS. Do not expose the app over plain HTTP or treat setting `HOST` as a deployment; hosting, TLS, storage persistence, and account administration must be configured separately. For local-only use, leave the default `HOST` unchanged.
